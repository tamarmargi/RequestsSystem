# תוכנית עבודה – מערכת ניהול פניות

Oct 23, 2026 ·@tamar

## סקירה

האפיון מפורק ל-11 אפיקים ו-47 משימות, בהיקף של כ-42 שעות נטו (כ-50 שעות כולל מרווח ביטחון של 20%), בהנחה שהקוד נכתב בעזרת Claude Code. הנחות בסיס: SQL Server עם EF Core, ‏.NET 8, ‏Angular 17+, ארכיטקטורת שלוש שכבות (Api, BL, DAL), IMemoryCache, ובחירה ב-Partial Success בעדכון Bulk.

**עקרונות החלוקה**

- כל אפיק (Epic) תואם לסעיף באפיון, כדי שהקשר בין דרישה למשימה יהיה ישיר (ראו מטריצת המעקב).
- כל משימה קטנה מספיק כדי להסתיים ביום עבודה אחד, ומגדירה תוצר שניתן לבדוק.
- חוזה ה-API נקבע מוקדם, כך שעבודת ה-Angular יכולה להתחיל במקביל ל-Backend.
- משימות שאינן קוד (תכנון DB, מדידת ביצועים, תיעוד, היערכות להרצה) מופיעות כמשימות מלאות עם הערכה.

**הערכת המאמץ** ניתנת בשעות עבודה נטו לכל משימה, וכוללת ניסוח ההוראה ל-Claude Code, סקירת הקוד שנוצר, בדיקה ידנית ותיקונים, ומסוכמת לכל אפיק בכותרתו. משימות שמסומנות "אופציונלי" אינן נכללות בסיכום.

## סיכונים והחלטות פתוחות

הסיכון העיקרי הוא בזמן: אם התקציב קצר מ-42 שעות, יש לקצץ קודם בתוספות ולא בסעיפי החובה.

**סיכונים**

- Testcontainers דורש Docker על מכונת הבודק וב-CI. גיבוי: SQL Server ב-Docker Compose ייעודי לבדיקות.
- חיפוש עם LIKE בכל מקום במחרוזת לא ישתמש באינדקס. גיבוי: לתעד כצוואר בקבוק ולהציע Full-Text (T9.3).
- COUNT מלא בכל שאילתת רשימה עלול להיות יקר. גיבוי: למדוד ב-T9.1 ולתעד.

**סדר קיצוץ אם הזמן נגמר**

1. T7.8 ו-T8.6 (אופציונליים).
2. CI ב-T10.5 (להשאיר Repo ציבורי בלבד).
3. Docker Compose מלא ב-T10.4 (להסתפק ב-DB ב-Docker והרצת API ו-UI מקומית).

**החלטות פתוחות**

- [x] Aggregations גלובליים ולא לפי פילטרים (מאפשר Cache)
- [x] Cache ב-IMemoryCache ולא Redis (שרת יחיד; Redis מתועד לריבוי מופעים)
- [x] Version בגוף הבקשה או בכותרת If-Match? — הוחלט: בגוף הבקשה (`version`), 409 באי-התאמה
- [x] קוד תגובה ל-Bulk: 200 עם תוצאה לכל פריט, או 207 Multi-Status? — הוחלט: 200 עם תוצאה לכל פריט (207 נתמך גרוע בצד הלקוח)
- [x] ChangedBy: משתמש מדומה מכותרת, או אימות בסיסי? — הוחלט: כותרת `X-User-Name` (ברירת מחדל "anonymous"), ללא אימות
